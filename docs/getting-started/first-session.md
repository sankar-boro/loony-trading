# Your First Session

This chapter is a guided tour, in the order that is safest to try things:
look at the dashboard, scan for signals, paper trade, backtest — and only much
later, trade live. Each step links to the chapter that covers it in depth.

## Step 1 — Open the dashboard

```bash
./loony.sh start
```

Open http://localhost:5163. The left sidebar lists every page; its footer shows
three status lights:

| Light | Green means | Otherwise |
|---|---|---|
| **Market** | NSE is open; shows minutes to close | Shows the next market open |
| **Bot** | A bot wrote `data/live_positions.json` in the last 5 minutes | "stopped" |
| **Token** | A valid Upstox token exists; shows its age | Red "missing" |

### Demo mode

With no valid token, an amber **DEMO DATA** banner appears across the top.
Prices, charts, signals and history are then synthetic: generated by
`data_engine/demo_ohlcv.py`, deterministic per symbol so the same symbol always
shows the same history. Demo mode exists so every page can be explored without
a paid API key. Nothing synthetic is ever presented as real — the banner stays
until a real token is present. Log in (see [Connecting to Upstox](upstox-access.md))
and the banner disappears on the next status refresh (every 10 seconds).

## Step 2 — Scan for signals

```bash
./loony.sh signals                 # python scripts/live_signals.py
```

The scanner fetches recent candles for each symbol, builds features, runs every
enabled strategy and prints the best signal per symbol with its stop-loss,
take-profit, confidence and the detected market regime. Useful flags:

| Flag | Effect |
|---|---|
| `--symbols RELIANCE,TCS` | Scan specific symbols |
| `--refresh 120` | Re-scan every 2 minutes |
| `--min-confidence 0.6` | Hide weaker signals |
| `--buy-only`, `--sell-only` | Filter by direction |
| `--all-signals` | Show every strategy's vote, not just the best |
| `--timeframe 1h` | Use hourly bars (also `1d`, `15m`) |

On the dashboard, the **Signals** page shows the MarketPulse composite score for
every stock — a different, research-oriented view described in
[Signals](../dashboard/signals.md).

## Step 3 — Paper trade

There are two paper-trading programs. Both use real prices and virtual money;
**neither places real orders**.

| | `scripts/paper_trade.py` | `python main.py --mode paper` |
|---|---|---|
| Prices | Polls Upstox every `--tick` seconds (default 60) | Real-time WebSocket feed |
| Portfolio | Its own virtual portfolio | The live bot's `RiskManager` with simulated fills |
| Dashboard | Feeds Positions, Trades, Daily P&L, equity curve | Feeds Positions (live-bot state file) |
| Best for | Watching the strategies trade during market hours | Rehearsing exactly what live mode will do |

Start with the standalone paper trader:

```bash
./loony.sh paper --symbols RELIANCE,TCS,HDFCBANK --tick 30
```

It redraws a terminal dashboard every tick: open positions with live P&L, the
day's realised P&L and a log of recent signals. It respects market hours (it
sleeps until the next open when NSE is closed), squares off intraday positions
at 15:14 IST, writes an end-of-day report at 15:35 and saves its state so a
restart within the hour resumes the same session. Everything it does is
covered in [Paper Trading](../operations/paper-trading.md).

While it runs, the dashboard's **Positions**, **Trades** and **Daily P&L**
pages fill in, and the **Bot** light turns green.

## Step 4 — Backtest an idea

Before trusting any strategy, test it on history. The quickest way is the
**Strategy Lab** page (`/backtest`) — pick symbols, strategies and a period,
and get metrics, an equity curve and optional Monte Carlo and walk-forward
results. From the command line:

```bash
./loony.sh backtest --symbol RELIANCE --days 730
python main.py --mode backtest          # every configured symbol
```

[Backtesting](../engine/backtesting.md) explains how the simulation works and
how to read the results honestly.

## Step 5 — Set up alerts and notifications

- Create **Watchlists** and **Alerts** in the dashboard to be told when a stock's
  composite score, price or signal crosses a level
  ([Watchlists and Alerts](../dashboard/watchlists-alerts.md)).
- Add `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` to `.env` to receive trades,
  risk events and alerts on your phone ([Notifications](../operations/notifications.md)).

## Step 6 — Run the bot in paper mode

```bash
python main.py --mode paper
```

This is the real trading bot with simulated fills: WebSocket prices, live bars,
the strategy engine, the risk manager, MIS squareoff, crash recovery. When the
market is closed it instead runs one pass of the strategies over the cached
history and exits. Run it for at least a week or two of real sessions and watch
its logs (`logs/trading.log`) and the dashboard. [Architecture of the Bot](../engine/architecture.md)
explains exactly what it does on every tick.

## Step 7 — Going live (only when ready)

```bash
python main.py --mode live
```

Live mode sends real orders. It refuses to start without a valid token,
reconciles its positions against your Upstox account on startup and every five
minutes, and alerts you on any mismatch. Before you run it:

- Read [The Trading Playbook](../operations/trading-playbook.md) end to end.
- Check `exchanges.upstox.default_product` (`CNC` delivery or `MIS` intraday)
  and the `risk` section in `config/settings.yaml` — start small.
- Make sure `scripts/auto_login.sh` runs every morning.
- Read [Position Safety](../engine/position-safety.md) so you know what the bot
  does after a crash, at 15:14, and when your account disagrees with it.
